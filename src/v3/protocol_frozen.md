# V3 prospective comparison protocol — frozen before held-out scoring

Frozen on 2026-10-18 after the method compatibility pilots and before any v3 held-out score. The v1 and v2 studies remain unchanged. The revision-pinned data and exact exclusions are in `data_manifest.json`. No v1/v2 held-out outcome was used to set this protocol.

## Question and endpoints

The primary question within each model, quantizer and byte-budget stratum is whether Alternis parent selection lowers held-out mean token negative log likelihood relative to tournament selection with the same candidate allowance. Random search is a second equal-allowance control. Conventional uniform quantization is the deployment baseline; a mixed-allocation gain over it is a combined search effect, not evidence that Alternis itself helped. Lower NLL is better. Report each text domain separately and a prespecified equal-weight average over AG News and IMDB blocks. ARC-Challenge accuracy, model bytes, preparation time, load time, prompt/decode throughput and peak process/MLX memory are secondary. Use paired seeds and report every seed, wins/ties/losses, mean and median paired differences and 95% paired bootstrap intervals. There is no cross-model pairing and no test-driven winner selection. Method-wide findings are exploratory; do not make a multiple-comparison-adjusted discovery claim.

## Models, data and selection

The first stratum uses Qwen3-1.7B because the Mac pilots established dense-model compatibility with most methods. Qwen3.5-2B is the second, architecturally distinct local model used in v1/v2; both exact revisions are in `data_manifest.json`. Methods with a verified implementation on only one model are assessed on that model alone. A non-Qwen architecture may be added only as a separate prospectively frozen stratum before its test data are scored; its results must not be conflated with existing paired comparisons.

AG News shuffled training indices 10000:15000 and IMDB shuffled training indices 0:5000 supply calibration, and the next 5000 records in each supply search validation. AG News indices 20000:25000 and the official IMDB test split supply untouched v3 text tests. The 400 ARC-Challenge questions exclude every previously used ARC-Easy ID. Tokenization, sample counts, revisions and hashes are frozen in `data_manifest.json`. The search fitness uses only the 32 mixed-domain `train_tokens` blocks per model; finalist choice uses the 128 mixed-domain `validation_tokens` blocks. Test blocks and ARC labels are accessed only after all finalist choices and model recipes are frozen. No held-out score may alter a search setting or model choice.

## Fair search within a stratum

At each supported budget, compare one conventional quantizer recipe with Alternis, tournament and random allocation searches on the same model, backend, calibration, validation data and candidate generator. Search arms receive the same informed starting population, per-seed random seeds, candidate count, precision choices and measured full-model byte cap. The cap includes quantizer scales, offsets, codebooks and metadata. Validate distinct scored candidates and record rejected/infeasible proposals. A method is included in a paired study only after mixed-precision export and reload, all chosen widths, actual-byte matching and inference have passed pilots; otherwise report its exact compatibility limit without inventing a pair.

The primary size target is no larger than the conventional 4-bit recipe's stored parameter bytes on that model and backend. Where a genuine lower-width conventional recipe and mixed configurations work, add a more aggressive target. Search candidate widths are selected from the method's verified supported widths before any test score, with at least one lower and one higher width around the conventional target. Keep methods in separate strata; do not equate a GGUF file byte count with an MLX parameter byte count without reporting both complete files and backend overhead.

The first full MLX-affine Qwen3-1.7B stratum has ten paired seeds 101, 211, 307, 401, 503, 601, 701, 809, 907 and 1009, with 48 distinct scored candidates per search arm and seed, 18 initial candidates, a three-parent pool and 2/4/8-bit choices under the exact uniform-4 parameter-byte cap. This yields 30 searches and 1440 distinct arm-level candidate scores. For heavier quantizers, use five paired seeds and a pre-search timing pilot to freeze a feasible equal per-arm count from 24, 16 or 12 candidates; the selected count, timing and source hash are saved before the first search. Do not reduce an active stratum's count or relax its limits.

## Method scope and execution limits

MLX affine, MLX dynamic, GPTQ, AWQ, DWQ, GGUF K/IQ, AutoRound and HQQ have at least a compatible native or CPU mixed-width pilot. Their full matched-budget studies are separate bounded strata. AQLM has only a tiny CPU inference pilot, SmoothQuant only a real single-matrix W8A8 CPU pilot, and TurboQuant only the paper's MSE vector stage. They must pass full-model or full-cache compatibility gates before held-out pairing; W8A8 and KV-cache results are separate questions from weight-only quantization. Preserve the paper's residual QJL stage before labeling an implementation full TurboQuant.

Run one supervised, checkpointed stratum at a time. Each retains its first-start deadline of 12 hours across restarts; the combined v3 directory must remain below 30 GB. Check candidate-level and stage-level checkpoints before work; never repeat a completed held-out evaluation. If a stratum cannot fit, record the exact reason and stop that stratum rather than changing its rules. Model and source revisions, data hashes, power/thermal context, measured bytes, wall-clock preparation, speed repetitions and reload checks accompany every result. Any later source change is logged with comparability impact and must precede the affected held-out score.
